# Fence each Adapter instance to one active runtime

Each Adapter instance permits one active runtime. A Core session claim issues a runtime ID that scopes every Adapter-originated Registration, heartbeat, Entity availability report, Entity enablement request, and Observation as well as every Command route until graceful release or lease expiry; Core rejects stale runtime IDs, and the SDK terminates a fenced session. This prevents duplicate Command execution and stale publications while preserving the stable Adapter slug across restarts. The runtime ID is a fencing mechanism rather than Adapter identity or authentication, because Hearth runs one trusted household and does not yet need replicated Adapters or dynamic NATS credentials. The incompatible route changes ship as one atomic version 1 Core, contract, SDK, and first-party Adapter cutover.
