# Use Home Assistant entity-registry IDs for Bridge Bindings

The Home Assistant Bridge resolves each configured `entity_id` through Home Assistant's entity registry and uses the registry entry's opaque `id` as the Binding key. Users configure only current entity IDs, while the registry ID preserves the canonical Hearth Device and Entity IDs when an entity is renamed. Entities without registry entries are rejected because their mutable entity ID is not sufficient durable identity. A deleted and recreated registry entry has a new identity; the core may reattach it automatically only when its current external entity ID identifies exactly one compatible existing Binding, and otherwise requires explicit reconciliation.

We chose registry IDs over user-managed Binding keys because the external system remains configuration authority and the common configuration should contain only entity selections. We chose them over Bridge-local persistence because the Adapter SDK remains stateless and identity survives replacement of the Bridge process. The registry fields are implemented by supported Home Assistant releases but are not fully documented as a stable public API, so real Home Assistant compatibility tests for every supported release line must verify lookup and rename stability. Failure of those tests blocks certification of that Home Assistant release.
