# Order canonical state by core receive order

The core will order canonical State by its monotonically assigned internal `receive_order`, without trusting wall clocks for conflict resolution. Core-owned `observed_at` is the JetStream server timestamp assigned when the Observation is durably received; adapter-supplied `adapter_received_at` records when the adapter acquired the value, and optional `source_updated_at` preserves an upstream last-change claim. Timestamps support operators and history, while `receive_order` provides a tie-free logical clock that survives wall-clock repetition or reversal. An `adapter_received_at` more than one minute ahead of `observed_at` is accepted but logged as clock-skew diagnostics. A delayed older report can therefore supersede a newer one, so adapters publish fresh Observations promptly and fetch a fresh snapshot after reconnect; protocol-native revisions may support stronger ordering later.
