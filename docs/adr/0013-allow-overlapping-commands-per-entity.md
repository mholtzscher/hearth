# Allow overlapping commands per entity

Hearth will allow multiple immediate Commands for one Entity to run concurrently rather than guarding, queuing, or superseding them. Each Command has an independent ID, durable history record, waiter, deadline, and linked outcome, which aligns first-slice behavior with common home-automation ecosystems and avoids introducing single-process or distributed coordination solely to serialize interactive intent. Interleaved Commands may both be satisfied at different observation times, one may time out after another changes the Entity, and a successful outcome may be immediately superseded; canonical State remains determined by normal Observation ordering.
