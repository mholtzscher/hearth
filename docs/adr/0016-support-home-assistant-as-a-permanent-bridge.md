# Support Home Assistant as a permanent inbound Bridge

This decision supersedes ADR 0003's requirement that the Home Assistant Adapter be disposable. Home Assistant connectivity remains isolated in a companion process behind Hearth's versioned NATS contracts, but the process is now a permanently supported inbound Bridge shipped and versioned with Hearth for use by any Household. Home Assistant remains responsible for bridged objects' configuration and lifecycle; Hearth represents selected objects as canonical Devices and Entities, and an object may remain bridged indefinitely or later transfer to native ownership without changing its canonical IDs.

We retain process and domain isolation because Home Assistant identifiers, service calls, payloads, and lifecycle assumptions still do not belong in the core. We chose a permanent inbound Bridge over a maintained migration tool because continued Home Assistant ownership is a valid end state, and over a bidirectional or full Home Assistant integration because either would introduce synchronization ownership, feedback loops, and Home Assistant concepts beyond the first supported product boundary. Permanent support requires release artifacts, installation documentation, compatibility testing, and visible runtime health; it does not yet make Hearth's Adapter contracts a stable third-party extension API.
